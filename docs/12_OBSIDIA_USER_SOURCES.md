## I. Source hierarchy for F0

When F0 finds conflicts, use this order:

```text
1. current executable code + tests
2. current frozen/runtime documentation
3. current domain evidence
4. recent master support documents
5. older architecture documents
6. historical AGI/visual documents
7. reconstruction from conversation
```

Historical material can reveal intended architecture, but it must not override a newer proven runtime without an explicit migration decision.

## J. Traceability target

Every major contract in this repository should eventually include:

```text
contract
  -> current code source
  -> current documentation source
  -> historical/intellectual source
  -> external donor/reference if any
  -> test proving current behavior
```

Example:

```text
VisualFingerprint
  -> Shazam Cognitif source
  -> visual corpus source
  -> current MMonde/SENS contract
  -> external feature/segmentation donors
  -> benchmark test
```

This keeps Brody World Physique Obsidia connected to the real Obsidia trajectory rather than turning into an isolated new project.
